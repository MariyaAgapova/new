# Nocturnal — многопользовательский читательский дневник

Совместное ведение читательского дневника: библиотека книг, трекер прогресса,
цитаты с реакциями и ветками комментариев, отзывы с оценками. Несколько
пользователей регистрируются и делят общие данные через сервер.

## Стек

- **Backend:** Node.js + Express + SQLite (встроенный `node:sqlite`, без нативных модулей)
- **Auth:** JWT-токены, пароли хэшируются bcrypt
- **Frontend:** чистый HTML/CSS/JS (single-file, dark mode + неон), без фреймворков

## Запуск

```bash
npm install
npm start
```

Откройте в браузере: http://localhost:3000

## Роли

- **admin** — входит в раздел «Управление» (кнопка в навбаре), может удалять любые
  пользовательские учётки (вместе с их книгами, цитатами, комментариями и отзывами).
  Собственную учётку удалить нельзя. Демо-админ: `admin@nocturnal.local` / `admin1234`.
- **user** — обычный читатель: библиотека, трекер, цитаты, комментарии, отзывы.

## Возможности

- Регистрация и вход (JWT, пароль хэшируется bcrypt)
- Общая библиотека: добавление книг (название, автор, жанр, страницы, обложка)
- Трекер прогресса чтения: слайдер страниц, статусы «Читают / Прочитано / В планах»
- Лента цитат: добавление, копирование в один клик, реакции (♥), ветки комментариев
- Отзывы и рейтинг (звёзды) по книгам
- Сводка по чтению на дашборде: общий прогресс и активность всех участников

## API (кратко)

- `POST /api/register`, `POST /api/login`, `GET /api/me`
- `GET /api/users`, `GET /api/books`, `POST /api/books`, `PATCH /api/books/:id`
- `POST /api/books/:id/reviews`, `GET /api/books/:id/reviews`
- `GET /api/quotes`, `POST /api/quotes`, `POST /api/quotes/:id/like`
- `GET/POST /api/quotes/:id/comments`
- `GET /api/activity`

## Структура

## Деплой на Render (бесплатный хостинг)

Дневник можно разместить в интернете так, чтобы он работал по постоянной
ссылке **без включённого компьютера**. Бесплатный вариант — [Render](https://render.com).

### Шаг 1. Выложите код на GitHub

Создайте репозиторий и загрузите файлы проекта (без `node_modules` и `nocturnal.db` —
они в `.gitignore`). Должны быть: `index.html`, `server.js`, `package.json`,
`package-lock.json`, `.gitignore`.

### Шаг 2. Создайте веб-сервис

1. Зарегистрируйтесь на [render.com](https://render.com) (кнопка «Sign up»).
2. Нажмите **New → Web Service**.
3. Подключите ваш GitHub-репозиторий.
4. Заполните настройки:
   - **Name** — любое (например `nocturnal-diary`)
   - **Region** — оставьте по умолчанию (или ближайший, например `Frankfurt`)
   - **Branch** — `main`
   - **Build Command** — `npm install`
   - **Start Command** — `npm start`
   - **Environment**: добавьте переменные:
     - `JWT_SECRET` — любой длинный случайный текст (например `my-super-secret-key-2026`)
     - `PORT` — оставьте пустым (Render задаст сам)
5. Нажмите **Create Web Service**.

Через 2–5 минут приложение будет доступно по адресу вида
`https://nocturnal-diary.onrender.com`.

### Шаг 3. Поделитесь ссылкой

Отправьте полученный адрес второму человеку. Он откроет его из любой точки мира,
зарегистрируется и увидит общие книги, цитаты и комментарии.

### Важно про данные на Render

- **Бесплатный тариф Render использует эфемерную файловую систему**: SQLite-база
  хранится на диске сервиса и **теряется при перезапуске/ре-деплое**. Данные
  (пользователи, книги, цитаты) могут сброситься.
- Для **постоянного хранения данных** на Render нужно либо:
  - платный тариф с **Persistent Disk**, или
  - внешняя БД (например бесплатный [Supabase](https://supabase.com) Postgres).
- Если вам нужна только демонстрация интерфейса — бесплатного тарифа достаточно.
- Если данные важны и должны жить долго — нужен персистентный диск или внешняя БД.

### Ограничения бесплатного тарифа Render

- Сервис «засыпает» после ~15 минут без запросов и «просыпается» с задержкой
  несколько секунд при первом обращении.
- До 750 часов работы в месяц (для одного сервиса — обычно хватает).
- Одна бесплатная БД Redis/Disk — платная; Persistent Disk платный.

### Переменные окружения (env)

| Переменная | Назначение | Обязательно |
|-----------|-----------|-------------|
| `JWT_SECRET` | Секрет для токенов | да |
| `PORT` | Порт (Render задаёт сам) | нет |
| `DB_PATH` | Путь к файлу БД (по умолчанию `nocturnal.db` в папке проекта) | нет |
